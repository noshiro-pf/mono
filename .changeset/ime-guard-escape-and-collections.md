`ts-ui-restrictions/require-ime-guard` checks Escape too, under the new message id `missingImeGuardOnEscape`: the Escape that cancels an input method's conversion closes a dialog or drops an edit just as the confirming Enter submits. The new `keys` option (default `["Enter", "Escape"]`) turns either off. The rule now also follows a key read into a `const` (`const key = event.key; key === 'Enter'`) and sees `includes` / `has` on a literal array or `Set`, or a `const` bound to one, that holds the key (`['Enter', ' '].includes(event.key)`). A guard function imported by name or through a namespace is matched by the name its module exports, so `import { isImeKeyDown as imeKey }` counts and another export imported as `isImeKeyDown` does not; an import of `default`, a local declaration and a method (`keys['isImeKeyDown'](event)` included) are matched by the name they are called by. A `guardFunctions` entry that named a renamed import by its local name (`imeKey` above) no longer matches it; name the export instead. A `const` bound to the event or to a member chain on it (`const native = event.nativeEvent`) is read as what it names, on the key's side and the guard's. A `new Set` counts only when `Set` is the standard one, not a value the file declares or imports. An optional chain in a guard's argument (`isImeKeyDown(event?.nativeEvent)`), inside a type wrapper or not, is read through.
