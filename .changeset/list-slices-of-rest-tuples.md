`List.ButLast`, `List.Tail`, `List.Take`, `List.Skip`, `List.TakeLast`, `List.SkipLast` and `List.Reverse` no longer claim elements a slice of a tuple with a rest or an optional element may not have. Such a tuple now yields an unsized array of its elements (`List.ButLast<readonly [1, ...string[]]>` is `readonly (1 | string)[]`, not the input type), except that `List.Tail` still removes a required first element exactly and `List.Reverse` still moves required leading elements to the end. `List.Reverse` and `List.SetAt` of a tuple with an optional element give a type instead of an excessive-depth error; `List.SetAt` answers an unsized array for it, as it already did for a rest. ts-data-forge's `Arr.butLast`, `Arr.tail`, `Arr.take`, `Arr.skip`, `Arr.takeLast` and `Arr.skipLast` return these types, so `Arr.butLast(names)[0]` on a `readonly [string, ...string[]]` is now `string | undefined`. Such a tuple is widened even where the old answer happened to hold: `List.Take<1, readonly [string, ...string[]]>` is now `readonly string[]`, so `Arr.take(nonEmpty, 1)` no longer returns a non-empty type. For an unsized array intersected with a brand (`readonly E[] & Brand`), these seven operations no longer return the branded type. `List.Partition` of a plain array or of such a tuple is `readonly (readonly E[])[]` instead of an excessive-depth error. `ConstrainedList` no longer rebuilds the positional half of a length-constrained tuple with an optional element as if it stopped at its shortest length (`ConstrainedList.Last` of `MinLengthArray<1, number> & readonly [1, 2?]` was `1`); the length bounds of such a type are still read from its union `length`. Results for tuples of one length, and for plain arrays apart from `Partition`, are unchanged, and each member of a union is now answered on its own.
