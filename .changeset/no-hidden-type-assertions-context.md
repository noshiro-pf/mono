`total-functions/no-hidden-type-assertions` reports a type argument the contextual type infers where no argument supplies it: a type parameter that only an omitted optional parameter, an empty rest parameter, a `NoInfer<…>` or the parameters of a callback given a lambda that leaves its parameter types to the context mention (`declare function g<T>(x?: T): T; const s: string = g();`). An `unknown` default no longer passes such a call (`parse<T = unknown>(): T` under `const s: string = parse()`), nor does a `never` default where the return type is the type parameter alone (`parse<T = never>(): T`); a `never` default the call does not overwrite still passes where the declared return type is a union with a member the type parameter is not in, as for `ok<S, E = never>(s: S): { ok: S } | { err: E }`. These need TypeScript 5.8 or later, whose checker gives the resolved type arguments; with an older one the rule reports what it did. In either, a cast of a function whose type parameter its value parameters mention only under `NoInfer` (`(h as (x: string) => string)('a')` for `h<T>(x: NoInfer<T>): T`) is reported as a cast of a hidden type assertion.
