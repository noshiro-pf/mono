`t.mergeRecords` checks a key that several of the records declare against each of their members, as its type, an intersection, says. It checked the last record's member alone, so merging `t.record({ id: t.int() })` with `t.record({ id: t.number() })` typed `id` as `Int` and accepted `1.5`. A key that the parts of a `t.intersection` given to `t.mergeRecords` share is now checked against each part's member in the same way. Records with disjoint keys are not affected.

Such a key is optional only when every record makes it optional. A copy of a member made by `t.optional`, `t.partial` or `t.required` counts as the same member, so `t.mergeRecords([R, t.partial(R)])` checks each key once, as required. What the key becomes depends on its members:

- Members that are all records are merged as `t.mergeRecords` merges records, keys, defaults and `fill` included. Such a merge is held to the limit of 10,000 record variants on its own, so records that share a key holding unions of records whose variants multiply past it make `t.mergeRecords` throw where they did not before. Records behind a `t.recursion` are merged on first use, once it can be resolved; the key's default is then a member's own default where every member accepts it, so a default a `t.recursion` gives itself to end its self-reference is kept, else the records merged's.
- When a member lists its values (`t.literal`, `t.enumType` or a union of those), the key becomes a `t.literal` or a `t.enumType` of the values every member accepts, so a discriminant every record repeats stays a literal, as `toJsonSchema` needs to find it. It defaults to the default of the last `t.literal` or `t.enumType` member whose default is one of those values, else to the first of them. This is decided when the merge is built, so not when a member is a `t.recursion`, or a union, intersection, refinement or brand of one.
- Any other members are intersected, and `toJsonSchema` writes the key as an `allOf` of them. The key's default is the first value that satisfies all the members among the members' defaults from the last back, the defaults of their union branches, and the defaults of their record branches merged, one branch of each member, as long as there are at most 64 such combinations. When none does, as for two number ranges that do not overlap, an optional key's default is `undefined`, which it accepts, where it used to be the last member's default; any other key's is still the last member's default. `fill` keeps a value that satisfies all the members, else takes the first repair that does, by a member's own `fill`, its union branches' or the merged record branches', else the default.

An optional key defaults to `undefined` when one of its members stores `undefined` as its default, as one made with `forceUndefinedDefault` does.

Members contradict each other when one lists its values and the other members accept none of them, or when they are records whose shared keys contradict, and the type is then `never` unless the key is optional, when it can only be absent. A combination of union variants with such a key is left out, as the type leaves it out, and when no combination is left, `mergeRecords` throws, naming the key (as a dotted path for a nested record). This is found when the merge is built, so not when a member is a `t.recursion`, or a union, intersection, refinement or brand of one; such members, and others that accept no value in common, such as `t.number()` and `t.string()`, are intersected: no value passes `is`, and the default is `undefined` for an optional key and the last member's default for any other.

`t.intersection` reads the `defaultValue` of the default type it is given on first use rather than when it is built, as `t.record` and `t.union` do, so that type may be a `t.recursion` whose definition is not initialized yet.
