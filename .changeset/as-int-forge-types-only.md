'eslint-plugin-ts-data-forge': patch
---

`prefer-as-int` reports a branded-number cast only when the type it names is ts-data-forge's: the name has no binding in the file (the global type from `ts-type-forge/global`) or is imported under that name from `ts-data-forge` or `ts-type-forge`. A local `type Int`, a type parameter, a project's own global `Int` that is not a ts-type-forge brand (with type information), or an `Int` imported from another module is no longer rewritten to `asInt()`, whose result is not that type; a value or a namespace of the same name (`const Int = 5`) does not hide the type. The fix is now written only when the operand is typed as a number at every layer of its type wrappers, since `asInt` takes a `number`: `u as Int` with `u` typed `unknown`, `any`, `string` or `number | undefined`, and `x as unknown as Int`, are reported without a fix and with a message that says the operand must be a number first, and without type information every cast but one of a number literal (`1 as Int`, `-1 as Int`) to a name imported from `ts-data-forge` or `ts-type-forge` is reported without a fix. An operand whose type is assignable to `number`, such as a type parameter constrained to it, is still fixed.
