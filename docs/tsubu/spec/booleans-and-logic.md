# boolean 厳密化と論理演算子

## 目標

truthiness(暗黙の boolean 変換)を言語から排除する。`@typescript-eslint/strict-boolean-expressions` のさらに強化版:

- `!`、`&&`、`||` の**左辺値も右辺値も**厳密に `boolean` 型のみ。
- 値の選択のための短絡評価 idiom(`x || defaultVal`、`cond && value`)は許可しない。デフォルト値は `??` で。

## 規則(提案)

| 文脈                                     | 規則                                                                    |
| :--------------------------------------- | :---------------------------------------------------------------------- |
| `if` / `while` / `do-while` / 三項の条件 | 式の型が `boolean` であること(`boolean` 以外の union も不可)            |
| `!x`                                     | `x: boolean` のみ                                                       |
| `a && b` / `a \|\| b`                    | `a`, `b` とも `boolean` のみ(結果も必然的に `boolean`)                  |
| デフォルト値                             | `x ?? defaultVal`(`??` は null-undefined 統一後は undefined 合体になる) |
| 存在チェック                             | `x !== undefined`、`Arr.isNonEmpty(xs)`、`str !== ''` など明示的な比較  |
| JSX の条件描画                           | `cond ? <X /> : undefined`(`cond && <X />` は禁止 — 現行 lint と一致)   |

## 条件による値の選択は三項演算子で(確定 2026-08-27)

条件に応じた値の選択は `a ? b : c`(条件が `boolean` であることは上表のとおり強制)を標準とする。入れ子で読みづらくなる問題への対策として if 式の導入も考えられるが、既存 TS 構文との互換を失うため採らない — 具象構文の差分をなるべく抑える設計方針に従う。型の世界の条件構文 `A extends B ? C : D` と字面が対応する点も三項演算子の利点。入れ子の可読性問題は、将来のパターンマッチ構文([future-syntax.md](./future-syntax.md) 候補 2)が受け皿になる。

## 短絡評価の意味論について(v1 の注意点)

両辺が boolean に制限された `a && b` でも、TS/JS の意味論上は短絡評価される(`a` が `false` なら `b` は評価されない)。v1 は意味を変更しない(D-2)ため、この評価順序自体は残る。したがって:

- `a && f()` の `f` が副作用を持つ場合、評価されるかどうかが `a` に依存する。この「条件実行を式に隠す」用法を排除するため、**論理演算子を式文(expression statement)として単独で書くことを禁止**する(`no-unused-expressions` 相当)。条件実行は `if` 文で書く。
- 純粋な boolean 演算としての `&&`/`||` は、短絡してもしなくても結果が同じ(副作用がなければ観測不能)なので、この制限下では短絡評価は実質「最適化」に落ちる。**言語仕様としては `&&`/`||` を純粋な boolean 代数の演算子と定義**し、オペランドに副作用を書かないことをスタイル規定(将来的にはチェッカー)で担保する。

## 強制手段

- v1: `strict-boolean-expressions`(全 allow オプション off)+ `no-unused-expressions` + `jsx-no-leaked-render`。「オペランドの副作用禁止」は完全な静的検査が難しいため段階導入(まず関数呼び出しをオペランドに置くことへの警告から)。

## TS へ戻るときの影響

なし。

## `Boolean(x)` / `!!x`(確定 2026-08-29)

どちらも禁止。`Boolean(x)` はコンストラクタ静的呼び出しの全面禁止(D-15 — [banned-syntax.md](./banned-syntax.md))に含まれ、`!!x` は暗黙変換 idiom として禁止。真偽の判定は `x !== undefined` / `Arr.isNonEmpty(xs)` / `s !== ''` など意図が伝わる比較で書く。
