　北國銀行は2027年1月、マルチクラウドで動作する次期勘定系システムを稼働させる。600万ステップに上るCOBOLアプリケーションを、わずか4カ月でJavaに書き換えた。生成AI（人工知能）の活用で思うような成果が上がらない中、あるメンバーから出た新発想が突破口を開いた。

製造と単体テストをわずか4カ月で終えた
（出所：日経クロステック）

　「このスケジュールは本気で言っていますか」。北國銀行の「次期コアバンキングシステム」の開発プロジェクトを率いる常務執行役員システム部長の新谷敦志は、あるパートナー企業の担当者からこう投げかけられた。勘定系システムの製造と単体テストをわずか4カ月でこなす想定だったからだ。

　次期システムの構築プロジェクトは2024年6月に始まり、2025年3月までに要件定義や論理設計などを終えた。それらに続くのが、既存のCOBOLアプリケーションをJavaに書き換える製造工程、そして必要な機能を満たしているかどうかを確認するテスト工程だ。預金や融資、為替といった現行システムの機能を漏れなく次期システムへ引き継ぐ必要がある。

　移行対象のオンラインプログラムは600万ステップに達する。しかも、銀行業務の根幹を成す勘定系システムだ。勘定系システムの製造と単体テストを4カ月でこなす計画と聞けば、あまりの期間の短さに、誰もが耳を疑うだろう。

　次期システムの稼働は2027年1月を予定する。新谷はカットオーバーのタイミングについて、他陣営の動向を踏まえて決めた。NTTデータなどの次期勘定系システムは2030年前後の稼働を目指している。外販も見据える次期システムをライバルに先駆けて稼働させるために逆算した結果が、異例の開発スケジュールだった。

　もちろん、品質も担保する必要がある。「プロジェクト発足当初から、製造やテストは生産性と品質の両方を意識して開発する方針だった」。北國銀行でシステム部開発グループ長を務める野田寛之は、生産性と品質のバランスをいかに図るかに気を配った。

　当初、野田らはCOBOLからJavaへの書き換えそのものに生成AI（人工知能）を適用した。具体的には、COBOLのロジックを基に、LLM（大規模言語モデル）を使ってJavaのコードを生み出し、生産性を高める狙いだったが、もくろみは外れる。「PoC（概念実証）を何度やっても、期待したコードを引き出せなかった」（野田）

　野田らの頭を悩ませたのが、生成AIが引き起こす「怠惰とゆらぎ」だった。怠惰とは「生成AIが勝手に省略してしまう」こと。「1回目と2回目の変換結果が異なる」というゆらぎは、自動変換の精度を下げてしまう。600万ステップのCOBOL脱却計画は行き詰まりかけた。

　「生成AIを使って変換ツールを作ってみてはどうか」

　そんな時、あるメンバーから出た新発想が突破口を開いた。新発想とは、プログラムの変換作業そのものに生成AIを使うのではなく、COBOLプログラムを入力するとJavaに変換するツールの開発に生成AIを適用するというものだ。ツールの仕様を決めるための現状分析などに生成AIをフル活用した結果、2カ月ほどでツールの大枠が完成した。

　この時点でCOBOLからJavaへの変換率は70％程度にとどまっていたものの、「あと1カ月あれば90％まで変換率を引き上げられそうだ」。そう見込んだ野田らはツールのブラッシュアップに力を注いだ。

　最終的に、全体の87％のアプリケーションについて、変換率を97％まで高めた。ツールで変換できなかった部分は手作業で補った。「ツールがなければ、これだけの短期間で開発やテストが終わらず、品質の担保も難しかった」。野田はこう振り返る。システムの内製力を磨き続けることで培った知見やノウハウが生きた。
