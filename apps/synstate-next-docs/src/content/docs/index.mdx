## Features

<CardGrid>
    <Card title="Simple state" icon="pencil">
        `createState` gives a state and its setter, and `createReducer` a state
        and its dispatch, as React's `useState` and `useReducer` do, for state
        the whole application shares. A counter is a
        state and a `subscribe`.
    </Card>
    <Card title="Async operators built in" icon="setting">
        `debounce`, `throttle`, `switchMap`, `fromAbortablePromise` and more. A
        search box that waits for typing to pause and drops stale answers is
        one pipeline, not a timer and a flag kept by hand.
    </Card>
    <Card title="Glitch-free through every operator" icon="approve-check">

An update computes each derived value once, after all of its parents, and calls subscribers only after that. The result of an async step arrives as an update of its own, under the same rules. No derived value is computed from a mix of old and new inputs. [Operators on signals](/mono/synstate-next/comparison/operators-on-signals/) shows what an operator written as an effect loses.

    </Card>
    <Card title="Cancellation is built in" icon="random">

With `fromAbortablePromise` inside `switchMap`, a newer query aborts the request of the one it replaces. Start a dialog's work inside an owner, and one `dispose()` when it closes stops the requests, timers and subscriptions it started: there is nothing to unsubscribe one by one. See [Owners and lifetime](/mono/synstate-next/guides/owners-and-lifetime/).

    </Card>
    <Card title="Unchanged values stop the update" icon="rocket">
        A value that comes out the same as before stops the update there, and
        what depends on it is not visited. An update costs the nodes it reaches,
        each computed at most once.
    </Card>
    <Card title="Types you can rely on" icon="seti:typescript">
        A state is an `InitializedObservable` with a `.value`; an event, which
        may hold nothing yet, is an `Observable` without one, and `pipe` works
        out which of the two an operator chain gives. A failed promise arrives
        as a `Result` value for the pipeline to handle.
    </Card>
    <Card title="Runs anywhere" icon="puzzle">
        A pipeline is a plain module with no framework behind it. A component, a
        test or a script that reads it gets the same values.
    </Card>
    <Card title="UI on synstate-next: synstate-dom-next" icon="window">

[synstate-dom-next](/mono/synstate-dom-next/) binds observables straight to the DOM, so the whole UI, async steps included, is one synstate-next graph. A component runs once, with no virtual DOM and no compiler.

    </Card>

</CardGrid>
