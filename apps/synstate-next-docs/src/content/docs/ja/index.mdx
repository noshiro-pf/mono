## 特徴

<CardGrid>
    <Card title="シンプルな状態" icon="pencil">
        `createState` は状態とセッターを、`createReducer` は状態と dispatch
        を返します。React の `useState`・`useReducer`
        と同じ形で、アプリケーション全体で共有できます。カウンターなら状態
        1 つと `subscribe` だけです。
    </Card>
    <Card title="非同期オペレーターを内蔵" icon="setting">
        `debounce`・`throttle`・`switchMap`・`fromAbortablePromise` など。入力が止まるのを待ち、古い応答を捨てる検索ボックスも、手で管理するタイマーとフラグではなく
        1 本のパイプラインで書けます。
    </Card>
    <Card title="どのオペレーターを通してもグリッチがない" icon="approve-check">

更新は、各派生値を親がすべて済んだ後に 1 回だけ計算し、その後で初めて購読者を呼びます。非同期の段の結果は、同じ規則に従う別の更新として届きます。古い入力と新しい入力を混ぜて計算される派生値はありません。effect で書いたオペレーターが何を失うかは [Signals の上のオペレーター](/mono/synstate-next/ja/comparison/operators-on-signals/) を参照。

    </Card>
    <Card title="取り消しの仕組みが組み込み" icon="random">

`switchMap` の中で `fromAbortablePromise` を使えば、新しいクエリは、置き換えた前のクエリのリクエストを中断します。ダイアログの処理を owner の中で始めれば、閉じるときの `dispose()` 1 回で、そこで始めたリクエスト・タイマー・購読がすべて止まり、1 つずつ購読を解除する必要はありません。[owner と寿命](/mono/synstate-next/ja/guides/owners-and-lifetime/)を参照。

    </Card>
    <Card title="変わらない値で更新が止まる" icon="rocket">
        計算し直した値が前と同じなら、更新はそこで止まり、それに依存するものは訪れません。更新のコストは、更新が届いたノードの数で、どのノードも 1 回の更新で多くても 1 回しか計算しません。
    </Card>
    <Card title="頼れる型" icon="seti:typescript">
        状態は `.value` を持つ `InitializedObservable`
        で、まだ値を持たないことがあるイベントは `.value` のない `Observable`
        です。オペレーターをつないだ結果がどちらになるかは `pipe`
        が計算します。失敗した Promise は、パイプラインが扱う `Result` の値として届きます。
    </Card>
    <Card title="どこでも動く" icon="puzzle">
        パイプラインはフレームワークに依存しない普通のモジュールです。コンポーネント・テスト・スクリプトのどこから読んでも同じ値が得られます。
    </Card>
    <Card title="synstate-next で UI を作る：synstate-dom-next" icon="window">

[synstate-dom-next](/mono/synstate-dom-next/ja/) は Observable を DOM に直接束縛するので、非同期の段も含めて UI 全体が 1 つの synstate-next のグラフになります。コンポーネントは 1 回だけ実行され、仮想 DOM もコンパイラもありません。

    </Card>

</CardGrid>
