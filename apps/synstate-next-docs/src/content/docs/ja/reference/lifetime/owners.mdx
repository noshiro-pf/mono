### `createOwner`

現在の owner の子として owner を作ります（どの owner の外ならルートになります）。

### `createRootOwner`

親を持たない owner を作ります。破棄するのは自分自身の `dispose` だけです。

### `getOwner`

`run` を実行中の owner を返します。なければ `undefined` です。

### `onCleanup`

`cleanup` を現在の owner に登録します。どの owner の外では、後始末が実行されることはないので警告します。`cleanup` の `this` は `unknown` なので、Observable のメソッド（`onCleanup(o.dispose)`）は型エラーになります。包んで渡してください。

### `untracked`

現在の owner がない状態で `fn` を呼びます。そこで作ったものは呼び出し元より長く生きます。

### `Owner`

`run` の実行中に作ったものはすべてこれに属し、`dispose()` がそれを破棄します。まず子の owner の分も含めて中のすべてを更新から外し、次に子の owner、後始末、ノードの順に、それぞれ新しいものから破棄します。そのため中の購読や束縛は、後始末が書き込んだ値も、破棄が引き起こしたことも受け取りません。後始末からは、破棄が始まった時点で派生ノードが持っていた値を読めます。例外は、射影やセットアップが自分の Observable を持つ owner を破棄する場合で、その前にそこで作ったものは後始末の書き込みを受け取ることがあります。`createOwner` か `createRootOwner` で作ります。

## 例

```tsx
import {
    createRootOwner,
    createState,
    getOwner,
    map,
    onCleanup,
    untracked,
} from 'synstate-next';

const [count, setCount] = createState(1);

const mut_log: string[] = [];

const owner = createRootOwner();

const shared = owner.run(() => {
    // What is created in `run` belongs to `owner`.
    count.pipe(map((n) => n * 2)).subscribe((n) => {
        mut_log.push(`doubled ${n}`);
    });

    onCleanup(() => {
        mut_log.push('cleaned up');
    });

    assert.strictEqual(getOwner(), owner);

    // `untracked` creates something no owner disposes.
    return untracked(() => count.pipe(map((n) => n * 3)));
});

owner.dispose();

setCount(2);

assert.deepStrictEqual(mut_log, ['doubled 2', 'cleaned up']);

assert.isTrue(owner.disposed);

assert.strictEqual(shared.value, 6);
```
