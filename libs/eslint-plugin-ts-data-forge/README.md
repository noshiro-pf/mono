# eslint-plugin-ts-data-forge

ESLint rules that steer TypeScript code toward [`ts-data-forge`](https://www.npmjs.com/package/ts-data-forge) idioms — e.g. preferring `Arr.isNonEmpty(xs)` over `xs.length > 0`, `isRecord(x) && hasKey(x, k)` over `Object.hasOwn(x, k)`, or `Num.safeParseInt` over `parseInt`. Most rules are auto-fixable; where the rewrite can change what the code does, the rule suggests it instead.

## Installation

```sh
npm install --save-dev eslint-plugin-ts-data-forge
```

Requires ESLint 9+ (flat config) and TypeScript. Some rules are type-aware and need a configured TypeScript project.

## Usage (flat config)

The plugin ships a `recommended` config preset that registers the plugin and
turns on **every** rule at `error`:

```ts
// eslint.config.mts
import { eslintPluginTsDataForge } from 'eslint-plugin-ts-data-forge';

export default [eslintPluginTsDataForge.configs.recommended];
```

Since the preset is a plain flat-config object, individual rules can be
adjusted by a later config entry:

```ts
// eslint.config.mts
import {
    eslintPluginTsDataForge,
    type EslintTsDataForgeRules,
} from 'eslint-plugin-ts-data-forge';

export default [
    eslintPluginTsDataForge.configs.recommended,
    {
        rules: {
            'ts-data-forge/prefer-range-for-loop': 'off',
        } satisfies Partial<EslintTsDataForgeRules>,
    },
];
```

Or register the plugin yourself and pick the rules one by one:

```ts
// eslint.config.mts
import {
    eslintPluginTsDataForge,
    type EslintTsDataForgeRules,
} from 'eslint-plugin-ts-data-forge';

export default [
    {
        plugins: { 'ts-data-forge': eslintPluginTsDataForge },
        rules: {
            'ts-data-forge/prefer-canonical-length-guard': 'error',
            'ts-data-forge/prefer-canonical-length-cast': 'error',
            'ts-data-forge/prefer-is-record-and-has-key': 'error',
            // ...enable the rules you want
        } satisfies Partial<EslintTsDataForgeRules>,
    },
];
```

## Imports from `ts-std-forge`

`ts-data-forge` re-exports part of [`ts-std-forge`](https://www.npmjs.com/package/ts-std-forge)
unchanged — `Optional`, `Result`, `pipe`, `isRecord`, `hasKey`,
`isNonNullObject` and the rest of what moved there — and tells new code to
import those from `ts-std-forge`. Every rule here treats such a name the same
whichever of the two packages it is imported from: it reports the same code, and
its fix reuses the import the file already has rather than adding a second one.
A name only `ts-data-forge` exports (`Arr`, `Num`, `isString`, …) is read from
`ts-data-forge` alone.

Use this plugin or [`eslint-plugin-ts-std-forge`](https://www.npmjs.com/package/eslint-plugin-ts-std-forge)
on a file, not both: their overlapping rules would report the same code twice.
This one is for code that depends on `ts-data-forge`.

## Rules

| Rule                                   | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prefer-canonical-array-slicing`       | Unify non-mutating array add/remove patterns into `Arr.tail`/`skip`/`take`/etc. A rewrite to `Arr.tail` or `Arr.butLast` is a suggestion, not a fix, since the call can fail to compile with TS2590 ([#2994](https://github.com/noshiro-pf/mono/issues/2994)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `prefer-canonical-length-guard`        | Normalize array-length checks to the canonical `Arr` guard (`xs.length > 0` → `Arr.isNonEmpty`, `Arr.isFixedLengthArray(0, xs)` → `Arr.isEmpty`, `Arr.isFixedLengthTuple(0, xs)` → `Arr.isEmptyTuple`, …).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `prefer-canonical-length-cast`         | Normalize a degenerate `Arr` length cast to the canonical one (`Arr.asMinLengthArray(1, xs)` → `Arr.asNonEmptyArray(xs)`, `Arr.asBoundedLengthArray(n, n, xs)` → `Arr.asFixedLengthArray(n, xs)`, …).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `prefer-arr-generate`                  | Replace the filter-and-map idiom `xs.flatMap((x) => (cond ? [f(x)] : []))` with a `for…of` loop in `Arr.generate` (type-aware). Suggests instead of fixing when the result is used as a mutable array, when a type annotation, a type wrapper or a comment would be dropped, when the receiver relies on a narrowing the generator function would not see, or when it is a `filter()` call.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `prefer-arr-is-array`                  | Replace `Array.isArray` with `Arr.isArray`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `prefer-arr-scan`                      | Report an accumulated value rebuilt for every element (`xs.map((_, i) => f(...xs.slice(0, i + 1)))`, or a `reduce` that appends to its accumulator) and point at `Arr.scan`. Fixes the `reduce` form.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `prefer-arr-sum`                       | Replace `xs.reduce((a, b) => a + b, 0)` with `Arr.sum(xs)` / `Arr.sumBy(xs, fn)`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `prefer-arr-uniq`                      | Replace `Array.from(new Set(xs))` / `[...new Set(xs)]` with `Arr.uniq(xs)` when `xs` is an array of primitives (type-aware). Suggests instead of fixing when the result is used as a mutable array.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `prefer-as-int`                        | Replace branded-number assertions (`x as Int`) with `asInt(x)`-style casts (type-aware). The fix adds a run-time check: `asInt` throws when the value is not such a number. The fix is written only when the operand is typed as a number at every layer of its type wrappers, so `u as Int` with `u` typed `unknown`, `any` or a `number` that may be `undefined` and `x as unknown as Int` are reported without a fix; without type information, so is every cast but one of a number literal (`1 as Int`, `-1 as Int`) to a name imported from `ts-data-forge` or `ts-type-forge`. A fixed call can be typed narrower than the cast (`asInt(0)` is `Int & 0`), so a `let` it initializes may no longer take another `Int`. Only ts-data-forge's own types are reported, imported from `ts-data-forge` or `ts-type-forge` or the global type of `ts-type-forge/global`: an `Int` declared in the file, a type parameter, a global `Int` that is not a ts-type-forge brand (with type information), or one imported from any other module is left alone. |
| `prefer-is-non-null-object`            | Replace `typeof u === 'object' && u !== null` with `isNonNullObject(u)`. Leaves a global or `declare`d `u` alone, which `isNonNullObject(u)` would throw on where it does not exist.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `prefer-range-for-loop`                | Replace C-style `for` loops with `for (const i of range(begin, end))` (type-aware). Fixes only when the arguments it writes have types `range` accepts (a `SafeInt` or an integer literal from -512 to 511, a positive one for the step), and otherwise at most suggests. It cannot always tell whether the end and the step stay the same across iterations, which `range` reads once, and can fix a loop whose end or step changes ([known cases](https://github.com/noshiro-pf/mono/issues/4135)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `prefer-is-record-and-has-key`         | Replace `Object.hasOwn(obj, key)` / `key in obj` with `isRecord(obj) && hasKey(…)`; `key in obj` is a suggestion unless `obj` is typed as a plain record (`Record<string, …>`) and the key is not a member of `Object.prototype`. `Reflect.has(obj, key)` is reported only on a plain record.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `prefer-num-safe-parse-int`            | Replace `parseInt(x, 10)` with `Result.unwrapOkOr(Num.safeParseInt(x), Number.NaN)`. Always a suggestion, since some strings parse differently.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `prefer-num-safe-parse-float`          | Replace `parseFloat(x)` / `Number(x)` with `Num.safeParseFloat`-based parsing. Always a suggestion, since some strings parse differently.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `no-unnecessary-type-guard`            | Flag `ts-data-forge` type-guard calls that do no narrowing (type-aware), including the variant guards such as `Optional.isNone` on a value typed `Some`. A constant guard handed to an assertion function (`assert.isTrue(...)`) is left alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `prefer-comparison-over-nullish-guard` | Prefer direct `=== null` / `!== undefined` over `isNull` / `isNotUndefined` calls.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `prefer-obj-over-entries-round-trip`   | Replace an `Object.fromEntries(Object.entries(o).map/filter/flatMap(…))` round trip with `Obj.map` / `Obj.filter` / `Obj.filterMap`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `prefer-pipe-map-nullable`             | Replace `pipe(x).map(mapNullable(fn))` with `pipe(x).mapNullable(fn)`. Suggests instead of fixing when an inline function's inferred result type has a literal or tuple part (which `mapNullable`'s `const` type parameter keeps and `Pipe.mapNullable` widens), or when a comment or type assertion would be dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `no-side-effect-import`                | Remove a side-effect-only `import 'ts-data-forge';`; the package declares `sideEffects: false`, so it binds no name and does nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
