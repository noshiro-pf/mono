# Predefined Branded Integer Types

This directory defines the branded **integer** number types. They are laid out
as a matrix of two independent axes so that the set stays **symmetric** (every
meaningful base × sign combination exists) and **complete** (no accidental
gaps).

Non-integer brands (`FiniteNumber`, `Float16`/`Float32`/`Float64`,
`InfiniteNumber`, `NaNType`, the sign-annotated `*Number` bases in `core.mts`,
etc.) are **not** part of this matrix and are maintained by hand.

## The two axes

- **Base** — the integer domain: `Int`, `SafeInt`, and the range-bounded
  `Int32`, `Int16`, `Uint32`, `Uint16`.
- **Sign** — the constraint on the value:

    | Sign key | Prefix        | Meaning                      |
    | :------- | :------------ | :--------------------------- |
    | `any`    | _(none)_      | any value in the base domain |
    | `>0`     | `Positive`    | strictly positive            |
    | `>=0`    | `NonNegative` | zero or positive             |
    | `!=0`    | `NonZero`     | non-zero                     |
    | `<=0`    | `NonPositive` | zero or negative             |
    | `<0`     | `Negative`    | strictly negative            |

## Type matrix

Each cell is the exported type name. `—` marks a combination that is
intentionally **not** generated (see notes below).

| Base ＼ Sign | `any`     | `>0` (Positive)   | `>=0` (NonNegative)                       | `!=0` (NonZero)                               | `<=0` (NonPositive)  | `<0` (Negative)   |
| :----------- | :-------- | :---------------- | :---------------------------------------- | :-------------------------------------------- | :------------------- | :---------------- |
| **Int**      | `Int`     | `PositiveInt`     | `NonNegativeInt` _(alias `Uint`)_         | `NonZeroInt`                                  | `NonPositiveInt`     | `NegativeInt`     |
| **SafeInt**  | `SafeInt` | `PositiveSafeInt` | `SafeUint` _(alias `NonNegativeSafeInt`)_ | `NonZeroSafeInt`                              | `NonPositiveSafeInt` | `NegativeSafeInt` |
| **Int32**    | `Int32`   | `PositiveInt32`   | `NonNegativeInt32`                        | `NonZeroInt32`                                | `NonPositiveInt32`   | `NegativeInt32`   |
| **Int16**    | `Int16`   | `PositiveInt16`   | `NonNegativeInt16`                        | `NonZeroInt16`                                | `NonPositiveInt16`   | `NegativeInt16`   |
| **Uint32**   | `Uint32`  | `PositiveUint32`  | —                                         | `NonZeroUint32` _(alias of `PositiveUint32`)_ | —                    | —                 |

## Ranges

| Base      | Range                     | Notes                                 |
| :-------- | :------------------------ | :------------------------------------ |
| `Int`     | any integer               | not necessarily representable exactly |
| `SafeInt` | `[-(2^53 - 1), 2^53 - 1]` | `Number.isSafeInteger`                |
| `Int32`   | `[-2^31, 2^31 - 1]`       | signed 32-bit                         |
| `Int16`   | `[-2^15, 2^15 - 1]`       | signed 16-bit                         |
| `Uint32`  | `[0, 2^32 - 1]`           | unsigned 32-bit                       |
| `Uint16`  | `[0, 2^16 - 1]`           | unsigned 16-bit                       |

`Int32` (`[-2^31, 2^31 - 1]`) and `Uint32` (`[0, 2^32 - 1]`) have **no containment relation**:
`Uint32` reaches higher than `Int32`'s max, while
`Int32` reaches below `Uint32`'s min. Their brand keys are set accordingly and
neither extends the other.

## `WithSmallInt` variants

Every generated primary type (and its aliases) also gets a `…WithSmallInt`
companion that unions in the small integer literals (`-40 … 39` by default) so
that small constants are usable without casts. For example:

- `IntWithSmallInt` = `-40 | -39 | … | 39 | Int`
- `PositiveUint32WithSmallInt` = `1 | 2 | … | 39 | PositiveUint32`

The literal range mirrors the sign of the base type (`NonNegative*` starts at
`0`, `Positive*` at `1`, `Negative*` ends at `-1`, and so on).

## Intentionally omitted cells

- **`NonNegativeUint32` / `NonNegativeUint16`** — redundant: an unsigned type is
  already `>= 0`, so this would equal the base type. Use `Uint32` / `Uint16`.
- **`NonPositiveUint32` / `NonPositiveUint16`** — would contain only `0`; not
  useful as a distinct type.
- **`NegativeUint32` / `NegativeUint16`** — the empty set; impossible to inhabit.

## Aliases

Some names denote the same type. They are all exported so both spellings type-check:

- `Uint` ≡ `NonNegativeInt`
- `NonNegativeSafeInt` ≡ `SafeUint`
- `NonZeroUint32` ≡ `PositiveUint32`, `NonZeroUint16` ≡ `PositiveUint16`
- and the matching `…WithSmallInt` pairs.
