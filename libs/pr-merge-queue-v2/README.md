# `pr-merge-queue-v2`

The from-scratch rebuild of [`pr-merge-queue`](../pr-merge-queue/README.md),
private until it replaces it. What it is to do, and how a v1 fix reaches it, is
[`spec/README.md`](./spec/README.md); the commands it is to have, their options
and exit codes, are [`spec/commands.md`](./spec/commands.md).

So far it holds:

- `src/github/`: the token, the repository a command acts on, the `fetch`
  transport the readers of [`pr-report-core-v2`](../pr-report-core-v2/README.md)
  send through, the session a writing command opens (`session.mts`), and the
  writes the commands share (`writes.mts`), each through `restWrite`.
- `src/cli/`: reading a command line.
- `src/commands/pr-report/`: `pr-report`, which reads one snapshot over REST,
  decides over it with `decideQueue` and prints the report. Its terminal and
  Markdown output and its JSON are v1's, save that v1 left each linked issue's
  title blank and its state `unknown`, which v2 reads, and that each issue
  carries its `start-issue` claim.
- `src/commands/startable-issues/`: `startable-issues`, which lists the issues
  to start next with `surveyIssues`, `heldThemes` and `orderByTheme`, and reads
  the `run-issue-resolver` record through `src/state/`.
- `src/commands/start-issue/`: `start-issue`, which decides with
  `decideStartIssue` or `decideReleaseIssue`, writes the claim, reads it back
  after a pause, and only then labels the issue.
- `src/commands/claim-pr/`: `claim-pr`, which reads the queue as `pr-report`
  does (`src/commands/pr-report/queue.mts`), decides with
  `decidePullRequestClaim` or `decideReleasePullRequestClaim`, writes the claim
  and reads it back after a pause.
- `src/config/`: `.github/unblock-prs.json`, v1's file unchanged, its schema
  generated by `gen:config-schema` and held equal to v1's.
- `src/git/`: the leased push and the restack, run with git in a throwaway
  worktree under the state root, a killed run's swept once stale; tested against
  real repositories made under the temporary directory.
- `src/commands/rework-pr/`: `rework-pr`, which decides with
  `decideReworkStanding`, `startSteps` and `doneSteps`, and runs the steps with
  the REST and GraphQL writes, the leased push and the restack;
  `src/git/rework-record.mts` keeps `start`'s record where v1 does.
- `src/commands/push-fixed-pr/`: `push-fixed-pr`, which reads the queue, decides
  with `decidePushFixedPr`, puts `skip-ci` on, pushes leased and carries the
  layers above along.
- `src/commands/pr-description/`: `pr-description`, which runs the description
  rules of `pr-report-core-v2` (`conventions/description.mts`, ported from v1
  with #3814's opening heading and mirrored code blocks) against GitHub and the
  files it pulls into.
- `src/commands/report-unowned-prs/`: `report-unowned-prs`, which reads the
  queue, plans with `planUnownedReports` against the reports open
  (`readUnownedReports`), and files the rest one at a time; `reportUnowned` is
  the step a caller that has read the queue already takes with what it read.
- `src/commands/open-pr/`: `open-pr`, which decides with `pr-report-core-v2`'s
  `decide/open-pr.mts` (v1's steps, ported with their tests) what to refuse
  before the push and what to declare, and reads and writes through
  `read/rest-open-pr.mts`; it never arms auto-merge.
- `src/commands/unblock-prs/`: the worker. Each cycle reads one snapshot over
  GraphQL, settles the set-aside comments (`settle.mts`), restacks the layers
  GitHub moved, plans with `pr-report-core-v2`'s `planCycle` (`plan/`: the
  in-flight watch, the conditions and the memory), executes the one step
  (`execute.mts`: the leased rebase in a worktree, arming, releasing, the
  labels), and keeps the memory in `~/.local/state/unblock-prs/worker/`
  (`src/state/worker-memory.mts`). Auto-fix runs in a worktree too
  (`src/git/auto-fix.mts`), and Regenerate inside the rebase
  (`src/git/regenerate.mts`). Checking ahead is decided by `pr-report-core-v2`
  (`decide/layers.mts`, which a page drawing the layers shares, and
  `plan/speculate.mts`), and done before the step (`layers.mts`, with
  `src/git/layers.mts` building the layers).
- `src/agent/`: the unattended loop the two commands below share: the Claude
  Code session runner (`claude.mts`, API key only), the round loop (`loop.mts`),
  and the interval and budget flags (`flags.mts`).
- `src/commands/run-unblock-prs-skill/`: `run-unblock-prs-skill`, which surveys
  the queue as the skill's first step does (`survey.mts`) and starts one
  `claude -p` session on the skill per pull request that is the skill's.
- `src/commands/run-issue-resolver/`: `run-issue-resolver`, which surveys the
  issues as `startable-issues` does and runs a pool of sessions under a budget
  (`pool.mts`), one issue each, keeping the record through `src/state/`.

Run a command from the repository root. On Node 25.4 or later it turns on
`fetch`'s use of `HTTPS_PROXY` itself; an older one needs `NODE_USE_ENV_PROXY=1`
behind a proxy, which does no harm on a newer one:

```sh
NODE_USE_ENV_PROXY=1 NODE_OPTIONS='--disable-warning=UNDICI-EHPA' \
  pnpm exec tsx --tsconfig ./tools/configs/tsconfig.tsx.json \
  ./libs/pr-merge-queue-v2/src/cmd/pr-report.mts --format markdown
```

The root scripts keep running v1 until the swap
([`spec/README.md`](./spec/README.md), "Migration").

## Who changes this package

As `pr-report-core-v2`: a fix to `pr-merge-queue` is not ported here as code. A
fix that changes a rule is written into the specification, with the test that
shows it, and reaches this package when that command is built or rebuilt here.
