record 関数の戻り値にユーザーコードで RecordType によるアノテーションをしようとすると、 Type 型のように値の型を渡せばよいわけではなく shape の型を渡さなければならない点で使いづらいのが現行 API の不満点です。 とはいえ、 Type は ts-fortress 無関係の値の validate 対象の値と同じ世界の型を第一引数に取っているため、現行の RecordType のような情報を持たせつつそのまま Type に完全に寄せることはできません。

ユーザーコードで Type と RecordType の違いを意識しなければならない場面は

1. mergeRecords の引数が RecordType[] 型という制限
2. defaultValue, fill とそれ以外の型で UnknownRecord が含まれるか否かが変わる点

が主なものだと思われます。
shape プロパティは実装上の都合で追加しているもののため、内部実装のラン タイムコードで `if (その Type が RecordType 型でもある場合)` という型ガードにより必要な時には情報を取り出すことにして、ユーザーコードでは shape の無い型のみ扱うようにすることはできそうです。
excessProperty の有無も現状 `& UnknownRecord` を一部メソッド結果に足すかどうかの違いを加えていますが、やはりこれをしないようにしてしまい shape と同様必要な箇所で取り出す方針にする手はありそうです。

また、 Type には Record 型のプロパティとして現れる場合にしか使われず、かつユーザーはアクセスする必要のない optional という key が公開されています。

以上を踏まえて、ユーザーに公開する API を整理しつつ機能を損なわないためにどのような実装方針が考えられるでしょうか。既存実装も確認してプランを考えてください。
